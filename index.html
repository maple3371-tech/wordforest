📄 JSON 형식 설명 보기

groups 안에 DAY/CHAPTER를, words 안에 단어를 넣어요. senses(뜻)는 여러 개 가능하고 뜻마다 예문이 따로 붙어요.

{
  "groups": [
    {
      "name": "DAY 1",
      "words": [
        {
          "word": "account for",
          "memo": "explain과 유의어",
          "senses": [
            {
              "meaning": "(이유 등을) 설명하다",
              "examples": [
                { "en": "He could not account for his absence.",
                  "ko": "그는 결석 이유를 설명하지 못했다." }
              ]
            },
            {
              "meaning": "(부분·비율을) 차지하다",
              "examples": [
                { "en": "Exports account for 60% of sales.",
                  "ko": "수출이 매출의 60%를 차지한다." }
              ]
            }
          ]
        }
      ]
    }
  ]
}

간단 형식도 됩니다: {"word":"abundant","meaning":"풍부한","examples":[{"en":"...","ko":"..."}]}
CSV/TSV도 가능해요 — 각 줄에 단어, 뜻, 영어예문, 예문뜻, 메모 순서.

단어 추가

블록이 쭉 생기면 채워 넣고 맨 아래 전체 저장을 누르세요 · 뜻이 여러 개면 ＋ 뜻 추가로 뜻마다 예문을 따로 적을 수 있어요 · **를 입력하면 ·로 바뀌어요.

Firebase 연결 가이드

  1. Firebase 콘솔에서 새 프로젝트를 만드세요.
  2. 빌드 → Authentication → 로그인 방법에서 Google을 사용 설정하세요.
  3. 빌드 → Firestore Database를 만들고(프로덕션 모드), 규칙을 아래처럼 바꾸세요. 
    rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == uid;
    }
  }
}

    ⚠️ 단어장이 그룹별 하위 문서로 저장되므로 /{document=**} 부분이 꼭 있어야 해요. 예전 규칙(match /users/{uid})만 있으면 단어장이 저장되지 않습니다.

  4. 프로젝트 설정 → 일반 → 내 앱에서 웹 앱(</>)을 추가하고 firebaseConfig 값을 복사하세요.
  5. 이 HTML 파일을 텍스트 편집기로 열어 맨 아래 FIREBASE_CONFIG 부분에 붙여넣으세요.
  6. Authentication → 설정 → 승인된 도메인에 이 파일을 여는 주소(예: localhost, GitHub Pages 도메인)를 추가하세요.

⚠️ 구글 로그인은 file://로 직접 연 파일에서는 동작하지 않아요. GitHub Pages, Netlify 등에 올리거나 로컬 서버(npx serve)로 열어주세요. 로그인 전에도 모든 기능은 이 기기 안에서 정상 동작합니다.
